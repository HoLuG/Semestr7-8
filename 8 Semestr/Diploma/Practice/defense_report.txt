1. ПОСТАНОВКА ЗАДАЧИ
==========================================================================

Рефал-5 — язык программирования, основанный на переписывании объектных
выражений. Программа задаётся функциями из правил «образец → результат»;
интерпретатор сопоставляет аргументы с образцами и строит результат.

Скорость интерпретатора зависит от того, как устроены операции над
объектными выражениями. В классических реализациях (Refal-5 PZ, Refal-5J)
выражение хранится как двусвязный список: конкатенация требует
копирования всего списка — O(N) на каждую операцию.

ЦЕЛЬ ПРАКТИКИ: довести до работающего состояния интерпретатор базисного
подмножества Рефала-5 на Java, где объектное выражение представлено
раскрученной (bootstrapped) двусторонней очередью по Окасаки.
Ключевое свойство: амортизированно константная конкатенация — O(1).

КОНКРЕТНЫЕ ЗАДАЧИ:
  1. Реализовать Expr<T> (ShallowDeque + DeepDeque, конкатенация по 4 случаям)
     и итеративный цикл нормализации на двух стеках.
  2. Написать тестовый каркас: юнит-тесты, интеграционные тесты,
     прогон внешних наборов автотестов.
  3. Оформить инструкцию пользователя: сборка, запуск, опции, коды возврата.
  4. Провести сравнительный замер с Refal-5 PZ и Refal-5J и подтвердить
     или опровергнуть теоретическое преимущество O(N) против O(N²).

2. СТРУКТУРА ДАННЫХ: РАСКРУЧЕННАЯ ДВУСТОРОННЯЯ ОЧЕРЕДЬ
==========================================================================

[ПОКАЗАТЬ: src/main/java/refal/deque/ — файлы Expr.java, ShallowDeque.java,
 DeepDeque.java, ExprOps.java]

Контейнер объявлен как запечатанный интерфейс:

  public sealed interface Expr<T> extends Iterable<T>
          permits ShallowDeque, DeepDeque { ... }

Sealed позволяет компилятору проверять полноту switch-выражений —
мы можем перечислить ровно 4 случая конкатенации без ветки default.

ДВЕ РЕАЛИЗАЦИИ:

ShallowDeque<T> — мелкий буфер:
  - Иммутабельный массив фиксированной ёмкости CAPACITY = 9.
  - Циклическое индексирование через Math.floorMod(head + i, CAPACITY).
  - При переполнении автоматически переходит в DeepDeque.

DeepDeque<T> — глубокий уровень:
  - Тройка ⟨front: ShallowDeque, mid: Expr<ShallowDeque>, back: ShallowDeque⟩.
  - Рекурсивная структура: mid сам является Expr, то есть может быть
    как ShallowDeque, так и DeepDeque следующего уровня — «раскрутка».
  - mkDeep автоматически схлопывает обратно в ShallowDeque, когда
    суммарный размер ≤ CAPACITY.

КОНКАТЕНАЦИЯ: 4 случая по типам операндов (SS, SD, DS, DD).
В случае Deep+Deep пограничные буферы склеиваются, concat вызывается
рекурсивно на средних очередях. Глубина рекурсии — O(log N), работа
на каждом уровне — константа. Итог: амортизированная константа.

3. ЦИКЛ НОРМАЛИЗАЦИИ И ОПТИМИЗАЦИЯ BulkPassive
==========================================================================

[ПОКАЗАТЬ: src/main/java/refal/runtime/Runtime.java,
           src/main/java/refal/runtime/ViewTerm.java]

ПОЛЕ ЗРЕНИЯ — sealed interface ViewTerm с вариантами:
  Passive(Term)       — пассивный атом или скобочный терм
  BulkPassive(Expr)   — блок пассивных термов (оптимизация)
  AngOpen(fn) / AngClose()    — вызов функции
  ParenOpen() / ParenClose()  — скобочный терм

ДВА СТЕКА:
  right — ещё не обработанные элементы поля зрения
  left  — уже пассивные элементы

Главный цикл: извлекаем из right по одному. Passive и AngOpen → в left.
При AngClose → снимаем left до парного AngOpen, собираем argsExpr,
вызываем функцию, результат кладём обратно в right.

Итеративный цикл (не рекурсивный) → независимость от глубины стека JVM.

ОПТИМИЗАЦИЯ BulkPassive:

Без оптимизации при подстановке e-переменной каждый терм кладётся
на right отдельным Passive — O(N) итераций. При следующей встрече
AngClose те же N элементов снимаются по одному — ещё O(N).
На программе с N итерациями → O(N²) суммарно.

С оптимизацией: вся e-переменная кладётся на right одним объектом
BulkPassive — O(1). При AngClose он вмешивается через Expr.concat —
тоже O(1) амортизированно. N итераций × O(1) = O(N).

------------------------------------------------------------------
КАК УСТРОЕН ТЕСТ И ПОЧЕМУ РАЗНИЦА В СЛОЖНОСТИ
------------------------------------------------------------------

Программа loop-select.ref (bench/loop-select.ref):

  Loop {
    s.Side (e.Acc) 0 = /* стоп */;
    s.Side (e.Acc) s.Rest
      = <Loop <Select s.Side (e.Acc A) (e.Acc B)> <- s.Rest 1>>;
  }

  Select {
    Left  t.Left t.Right = Right t.Left;
    Right t.Left t.Right = Left  t.Right;
  }

Программа стартует как <Loop Left () N>.
На каждой итерации:
  1. Строятся два скобочных терма: (e.Acc A) и (e.Acc B).
     Каждый из них содержит внутри ВЕСЬ текущий аккумулятор e.Acc.
  2. Select выбирает один из них в зависимости от стороны (Left/Right).
  3. Выбранный терм становится новым (e.Acc) на следующей итерации.

Как меняется e.Acc по шагам (при N=5):
  Итерация 1: e.Acc = ""        → выбирается "(A)"
  Итерация 2: e.Acc = "A"       → выбирается "(A B)"
  Итерация 3: e.Acc = "A B"     → выбирается "(A B A)"
  Итерация 4: e.Acc = "A B A"   → выбирается "(A B A B)"
  ...

На итерации k длина e.Acc равна k-1 термов.

ПОЧЕМУ СПИСОЧНЫЕ РЕАЛИЗАЦИИ — O(N²):
  Refal-5 PZ и Refal-5J хранят выражение как связный список термов.
  Чтобы построить (e.Acc A), нужно скопировать весь список e.Acc
  и дописать A в конец — это O(k) операций копирования.
  То же для (e.Acc B) — ещё O(k).
  Итого на итерации k: O(k) работы.
  За N итераций: O(1) + O(2) + ... + O(N) = O(N²).

  На N=20000 это означает порядка 200 миллионов операций копирования —
  отсюда и 1059 мс у PZ и 1348 мс у Refal-5J.

ПОЧЕМУ НАША РЕАЛИЗАЦИЯ — O(N):

  Ключ — два механизма работают вместе:

  1. BulkPassive: когда нормализатор подставляет значение e.Acc
     в правую часть правила, весь Expr<Term> кладётся на стек
     ОДНИМ объектом BulkPassive — за O(1), без перебора элементов.

  2. Expr.concat — раскрученная очередь по Окасаки:
     Сборка (e.Acc A) — это Expr.concat(e.Acc_expr, singleton(A)).
     Структура устроена так, что конкатенация не копирует данные,
     а лишь перестраивает указатели в дереве буферов.

  Амортизированная оценка: одна конкатенация — O(1).
  N итераций × O(1) = O(N).

КАК РАБОТАЕТ РАСКРУЧЕННАЯ ОЧЕРЕДЬ (ПОЧЕМУ КОНКАТЕНАЦИЯ O(1)):

  ShallowDeque — это кольцевой массив на 9 элементов.
  Он всегда хранит от 5 до 9 термов (MIN_FILL = 5).
  "Дырки" — незаполненные слоты массива с обоих концов — это запас
  для pushFront и pushBack без перевыделения памяти.

  DeepDeque хранит тройку: ⟨front, mid, back⟩, где:
    front и back — ShallowDeque (буферизованные концы),
    mid — рекурсивный Expr<ShallowDeque> (средняя часть).

  При конкатенации двух DeepDeque: крайние буферы (a.back и b.front)
  склеиваются в один ShallowDeque (≤ 18 элементов → 2 буфера),
  а средние части соединяются рекурсивно — но глубина рекурсии
  ограничена O(log N), и на каждом уровне работа константная.

  Ключевой инвариант: concat никогда не перебирает отдельные термы.
  Он только переставляет указатели на буферы — количество операций
  не зависит от числа термов внутри.

ИТОГ ДЛЯ ЗАЩИТЫ:
  Списочный интерпретатор на итерации k "физически переписывает"
  k термов — накопленная работа растёт как площадь треугольника N×N/2.
  Наш интерпретатор на той же итерации переставляет 2–4 указателя
  в дереве буферов — работа не зависит от k.
  График это прямо демонстрирует: у PZ и R5J — парабола, у нас — прямая.

ТЕСТОВАЯ ПРОГРАММА Loop/Select:
  N итераций, каждая конкатенирует растущий аккумулятор e.Acc.
  При связном списке: O(N²) суммарно.
  При раскрученной очереди + BulkPassive: O(N) суммарно.
